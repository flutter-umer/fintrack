# FinTrack Mobile Application

Flutter mobile application for the FinTrack personal finance management system.

## Overview

This directory contains the Flutter application that serves as the user-facing client for FinTrack. The application currently implements a complete authentication layer and a placeholder home screen. Financial data features (transactions, budgets, analytics, savings goals) are planned but not yet implemented.

## Technology Stack

| Technology | Version |
|---|---|
| Flutter | 3.x (stable channel) |
| Dart | ^3.13.4 |
| Firebase Core | ^4.15.0 |
| Firebase Authentication | ^6.7.0 |
| Google Sign-In | ^6.2.0 (pinned — v7 is API-incompatible) |
| Google Fonts | ^6.2.1 |

There is no state management library, HTTP client, local storage package, or charting package in the project at this time.

## Implemented Features

### Authentication

- Email and password registration
- Email and password login
- Google Sign-In via Firebase Authentication
- Persistent authentication state across app restarts
- Password reset by email
- Client-side form validation on login and registration screens
- Logout (signs out from both Firebase and Google)
- Firebase error codes mapped to user-readable messages

### Screens

| Screen | Status |
|---|---|
| Splash screen | Implemented (branded marketing screen with static data) |
| Login screen | Implemented |
| Registration screen | Implemented |
| Home screen | Placeholder only (hardcoded static values, no real data) |

All financial data visible on the splash and home screens is hardcoded. No data is read from or written to any backend or database.

### Reusable Widgets

- `GlassCard` — frosted-glass card container using `BackdropFilter`
- `GlassTextField` — styled text input with validation state
- `PrimaryButton` — gradient action button with loading state
- `SocialButton` / `GoogleIcon` — social login button with custom Google icon painter

## Firebase Configuration

Firebase Authentication is the identity provider. The Firebase project must have the Email/Password and Google sign-in methods enabled in the Firebase Console.

The following files contain Firebase configuration and must not be committed to source control:

- `lib/firebase_options.dart` — generated by the FlutterFire CLI; contains platform-specific API keys
- `android/app/google-services.json` — Android Firebase configuration
- `ios/Runner/GoogleService-Info.plist` — iOS Firebase configuration

If these files are missing, run the FlutterFire CLI to regenerate them:

```bash
dart pub global activate flutterfire_cli
flutterfire configure
```

## Running the Application

Install dependencies:

```bash
flutter pub get
```

Run on a connected device or emulator:

```bash
flutter run
```

For Android, Google Sign-In requires the debug keystore SHA-1 fingerprint to be registered in the Firebase Console under Project Settings > Your Apps > Android app. To get the fingerprint:

```bash
cd android && .\gradlew.bat signingReport
```

## Supported Platforms
